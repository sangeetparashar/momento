## 4. Key Decisions & Rationale

| Decision | Why | Alternatives Considered |
|----------|-----|------------------------|
| **Use `/render/image/public/` instead of fighting `/object/public/`** | Supabase platform hard-codes `no-cache` on `/object/public/` — confirmed via direct test of byte-changed files (still served `no-cache` from CDN). `/render/image/` respects metadata AND auto-compresses. | Fight the gateway via byte-append + raw header sends (worked on origin but not on serve path); contact Supabase support (slow turnaround); migrate to Cloudflare R2 (premature) |
| **Byte-append (single 0x00) to force CF cache invalidation** | Supabase dedupes identical-bytes re-uploads. The trailing null byte changes etag without breaking any image decoder (decoders stop at EOI/IEND markers). | Modify file content (risk of corruption); use `move()` then `move()` back (brief 404 window); wait for natural CF eviction (could be forever for hot files) |
| **Keep Supabase Pro AND add CF Stream later** | Supabase is sunk cost for the month + still pays for DB + images + avatars. CF Stream as net-new $15/mo for dedicated video infra. | Drop Supabase + go full CF Stream (loses DB perks); keep Supabase video forever (no HLS, no analytics, slow uploads continue) |
| **Defer CF Stream for 1-2 weeks** | User wants to see if `react-native-compressor` alone solves the upload-speed complaint. If it does, CF Stream may not be necessary. | Build CF Stream now (premature); migrate everything to Mux (better DX but 30-50% more expensive at this scale) |
| **MediaImage primitive instead of inline wrapping at 13 sites** | Inconsistent recyclingKey/cachePolicy across sites; some sites called `transformMediaUrl(x)` twice per render; next migration (CF Stream HLS detection) would touch 14 files instead of 1. | Leave inline (working but fragile); use a higher-order HOC (overkill for the surface) |
| **Separate `/api/_keep-warm` endpoint for cron, gated on CRON_SECRET** | `/api/health` should stay public for ops/uptime monitoring. Cron endpoint shouldn't be a free probe surface. | Gate `/api/health` itself (breaks ops); leave cron unauthenticated (theoretical DoS amplification) |
| **Auth runs BEFORE rate-limit on admin endpoints** | Rate-limit-then-auth used IP as key (rate-limit ran before userId was known). Unauthenticated attackers could burn through quota; legit admins shared cap with anyone on same NAT. | Keep order (insecure); add a second layer of auth-aware rate limiting (overcomplicated) |
| **Hold submit until tomorrow** | User wanted to ship "stable and clean builds later" — last build had bugs the audit caught. Tomorrow's submit is the clean version. | Submit immediately (risk of buggy version reaching beta users); discard build (waste of 25-min build time) |

## 5. Bugs, Failures & Lessons Learned

**This section is the highest value. Read before touching anything related.**

- **Supabase's `/object/public/` gateway ALWAYS returns `cache-control: no-cache`** — platform-level override, not configurable, regardless of `metadata.cacheControl` or bucket settings. Spent ~2 hours fighting this before discovering `/render/image/public/` is the workaround for images. **No equivalent for videos.** Confirmed via direct test where a fresh upload with `Cache-Control: max-age=31536000` request header still served `no-cache` from `/object/public/`.

- **Supabase JS SDK `.update({cacheControl})` pre-wraps with `max-age=`** — passing `'max-age=31536000, immutable'` produced stored value `max-age=max-age=31536000, immutable`. SDK code at uploads adds `max-age=${value}` unconditionally. **Workarounds**: pass just the numeric value `'31536000'` (loses `immutable`), OR bypass the SDK and PUT directly with a raw `Cache-Control` header.

- **Identical-bytes re-upload to Supabase is deduped** — `.update(path, sameBlob, { upsert: true })` returns 200 with the Key+Id but doesn't actually create a new version. Same etag, same `last_modified`, same `version` field in `/info` endpoint. **This means CF cache is never invalidated for "fix the cache-control on this existing file" use cases.** The byte-append trick is the workaround.

- **The `eas update` CLI auto-mutates `app.json` and `package.json`** on first run — adds `expo-updates` to deps, adds `runtimeVersion` to ios/android sections, adds `updates.url`. Also **duplicates Android permissions** (had to dedupe). If you commit before noticing, those changes ride along.

- **Pre-existing bug exposed by compression**: `useUpload.ts:140` did `mimeType.split('/')[1]` to derive file extension, producing `.quicktime` for iPhone QuickTime captures. The feed's VIDEO_EXTENSIONS arrays (`home.tsx:33`, `explore.tsx:29`) only check `.mp4/.mov/.webm`, so iOS-uploaded videos render as broken images. **Masked while video uploads were rare** (50MB cap blocked most). Once compression ships and more videos upload, this becomes the dominant failure mode. **Fixed in `4316adf` via explicit MIME_TO_EXT map**.

- **`transformMediaUrl` URL substring matching was fragile** — initial impl used `url.includes('/storage/v1/object/public/')` which would also match `https://attacker-cdn.com/storage/v1/object/public/foo.jpg`. No data triggers this today but if avatars/banners ever come from external CDNs, would silently break. **Fixed via host regex `/(\.supabase\.(co|in))\/storage\/v1\/object\/public\//`**.

- **Rate-limit before auth = IP-keyed** — both new admin endpoints initially called `applyRateLimit` before `requireAdmin`. Since `userId` is undefined at rate-limit time, `getRateLimitId` falls back to `x-forwarded-for` IP. Unauthenticated attackers could burn quota with rotating IPs; legitimate admins shared cap with anyone on same NAT. **Always run auth FIRST, pass `user.id` to applyRateLimit**.

- **`creators/apply/route.ts` invalidated `userProfile + creatorProfile` but NOT `creatorLeaderboard()`** — self-applied creators (SKIP_KYC dev mode) didn't appear in leaderboard for up to 5 min. The new admin endpoint included the leaderboard key correctly, which made the gap visible by comparison. **Centralized via `invalidateCreatorCaches(userId)` helper in `lib/redis.ts`**.

- **`Cache-Control: immutable` on user-uploaded content makes moderation takedowns slow** — if a post is later determined to be abuse/CSAM, deleting the Supabase row removes origin but CF edge nodes continue serving cached bytes (potentially for hours). Clients that already fetched will keep it indefinitely per the `immutable` directive. **Document a takedown runbook OR force URL rotation on delete** (not yet implemented; flagged as future operational concern).

- **EAS submit auto-attaches to existing TestFlight groups** — once a build is submitted, it auto-attaches to Internal (Momento Core Creators) and External (Momento Public Beta) groups. No manual click needed. Apple Beta App Review typically auto-passes for re-submissions to already-approved apps (no human review).

- **The /tmp backup dirs from `fix-cache-control.ts`** linger after the script runs. World-readable on macOS. Contains user-uploaded images (no PII in current state, but worth knowing). Path pattern: `/tmp/momento-cache-fix-backup-<unix-ms>/`. Cleanup not automated.

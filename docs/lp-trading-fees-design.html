03On Bankr (bnkr) — important reframing

You flagged Bankr specifically, and the research changed how to think about it. Bankr is not infrastructure to integrate into — it's a peer doing exactly what Momento would do. Per Bankr's own docs, it lets users "deploy a fair-launch token on Base (via Clanker) or Solana (via Raydium LaunchLab)" verified: docs.bankr.chat. It charges 1.2% swap fee on Base, 57% to creator verified — i.e. Bankr is a Clanker interface keeping the interface slice.

The takeaway: Bankr proves the "be a launchpad interface and keep a per-swap cut" model works at scale. There is no Bankr partner/white-label fee-share API for a third-party app to earn through could not find one; Bankr's @bankr/sdk drives its agent, not white-label launches. So: don't integrate Bankr — integrate the layer beneath it (Clanker / LaunchLab) directly and capture the slice Bankr keeps for itself.

06How fees would flow (Meteora DBC path) — tap a step

07Unified fee configuration model

Goal: every fee leg reads from one coherent config, so rates are tunable without code changes.

  • MOMENTO_PLATFORM_FEE_BPS — trading fee (exists, 400 = 4%). Already wired both chains.
  • MOMENTO_FEE_WALLET / BASE_FEE_WALLET — per-chain fee sinks (exist).
  • New: MOMENTO_LP_FEE_CLAIMER — the Solana wallet registered as Meteora fee_claimer (where the partner share accrues).
  • New: MOMENTO_CREATOR_FEE_PCT — how much of the partner share we pass to the creator (e.g. 50%). Drives creator_trading_fee_percentage in the DBC config key.
  • New table (additive raw SQL, like promotion_logs): fee_events — log every claim/accrual for accounting & the future reconciliation dashboard.
⚠ Custody / compliance — flag before building Launching tokens + holding pool fee-claim authority is a materially bigger regulatory surface than swaps. The feeClaimer wallet accrues real revenue; creator-token issuance may implicate securities/MSB questions depending on jurisdiction and how "creator tokens" are marketed. Get a legal read before shipping the launchpad leg. The trading-fee leg (already live) is lower-risk by comparison.

09Decisions for you

Q1 — Chain. Solana + Meteora DBC (my rec: verified 80% partner share, deepest existing infra, schema already fits, bonding-curve lifecycle) — or a Base option if Base/Farcaster creator-coin culture is the target? Base best picks: Clanker v4.1 (most battle-tested), Flaunch (cleanest white-label RevenueManager), or Zora (simplest — auto-paid 20% platformReferrer).
Q2 — Launch model. Bonding-curve (Meteora/Raydium: start cheap, graduate once it fills) or direct-LP (Clanker/Flaunch/Zora: immediate Uniswap pool)? Partly downstream of Q1, partly a product call.
Q3 — Creator fee split. Of our partner share, what % do we pass to creators? Comps: pump.fun ~50%, Jupiter 50%, Clanker-bot 80%, Zora 50%, Bankr 57%. Generous splits drive creator acquisition but cut platform revenue.
Q4 — Scope of "trading config." Is the existing single MOMENTO_PLATFORM_FEE_BPS enough, or do you want per-creator / per-token configurable trading fees (more complex, needs a config store + admin UI)?
Q5 — Legal. Do you have / want a compliance read before the launchpad leg? Strongly recommended given fee custody + token issuance.

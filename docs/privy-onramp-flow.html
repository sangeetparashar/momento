Recommendation: Privy widget onramp (no Bridge account, no fee) — ship fast now, add the fee later only if you want it

You asked the decisive question: do I need a separate service account? Answer — only the fee path does. The fee requires a standalone Bridge account + business KYB + a USD payout account. The no-account path is Privy's built-in widget onramp (useFiatOnramp): it runs inside the Privy modal you already have, supports Base AND Solana, takes cards + Apple/Google Pay — but exposes no developer fee. Since you're happy to skip the fee for a quick rollout, this is the pick.

*One caveat on "no account" The widget path still needs a one-time dashboard enablement: Privy Console → Plugins → MoonPay Fiat On-Ramp → Request Access. Privy's team reviews and flips it on, and MoonPay may ask for basic KYB info about your product (this is Privy/MoonPay's compliance, not you opening a MoonPay merchant account). It's a request-and-wait, not an integration build. No API keys to manage, no payout account, no separate login.

02Why this is a transition, not a rebuild

We already have: Privy login wired end-to-end, embedded wallets for both Solana and Base per user, a FundWalletModal + useOnramp hook + /api/wallet/onramp route (currently Ramp/MoonPay/Transak via raw WebView URLs), and the {success,data} envelope. The widget onramp replaces the hand-built WebView URL plumbing with Privy's native hook — fewer moving parts than today, not more. We delete provider-URL builders; we add one hook call.

Net simplification Moving to useFiatOnramp lets us retire the bespoke MoonPay/Ramp/Transak URL builders in /api/wallet/onramp/route.ts and the Transak 2-step token dance. Privy handles provider selection, region routing, KYC, and the payment UI. We keep our wallet-address logic and the modal shell.

05On the fee — explicitly deferred

You're okay skipping the onramp fee in exchange for the quick, no-account rollout. So:

  • Onramp fee — none on the widget path. Users buy USDC at the provider's rate; Momento takes nothing on the onramp itself.
  • Trading fee — still live. Your 4% Jupiter fee (MOMENTO_PLATFORM_FEE_BPS=400 → MOMENTO_FEE_WALLET) is untouched and still earns once funded USDC is traded. already shipped
  • LP fee — future, unchanged by this decision.

So the revenue model still works — we simply don't tax the entry of money, only its use (trading) inside the app. If onramp volume later justifies the Bridge KYB lift, the fee path is documented above as a clean upgrade.

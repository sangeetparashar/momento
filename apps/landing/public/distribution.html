03 Keeping Supabase Awake

Pick one of three strategies. The decision is mostly about cost vs. reliability for external testers.

Option A · Recommended once you have testers

Upgrade to Supabase Pro ($25/mo)

Removes auto-pause entirely, adds 7-day point-in-time recovery, daily backups, larger DB, and 8 GB egress.

Screen-by-screen:

  1. Open the project's billing page
    Supabase Dashboard→ Left sidebar: Settings→ Billing https://app.supabase.com/project/phlkstaghvbwacmzuihr/settings/billing
  2. Click "Change subscription plan"
    It's the prominent button at the top of the page. Pick Pro ($25/mo base).
  3. Enter card details and confirm
    Pro tier activates immediately. Auto-pause stops applying.
Option B · Free + cron

Vercel Cron — keep-warm ping

Add a scheduled GET to /api/health every 6 days. Free if it fits in your Vercel cron budget.

Step-by-step (code change):

  1. Add a cron config to apps/api/vercel.json
    {
  "crons": [
    { "path": "/api/health", "schedule": "0 9 */6 * *" }
  ]
}
    Runs at 09:00 UTC every 6 days. Cost: $0 on Hobby tier.
  2. Commit and push
    Vercel picks up cron config automatically on next deploy.
  3. Verify it ran
    Vercel Dashboard→ momento-api project→ Settings tab→ Cron Jobs https://vercel.com/<org>/momento-api/settings/crons
    You'll see the last invocation time and status here.
Fragility: A single cron miss won't pause Supabase (7 days threshold > 6-day cron), but a string of failures can. Monitor.
Option C · Do nothing

Accept the risk (solo dev only)

Fine while it's just you. Not fine the day someone else opens the app and hits 503. Don't pick this option for TestFlight or Play Internal Testing rollouts.

iOS · Phase 7

Physical iPhone Dev Build~20-35 min build + 5 min install

Blocked: needs iPhone in hand

Generates a signed development build for a specific iPhone UDID. Once installed, you get hot-reload via Metro just like on the simulator.

  1. Plug in the iPhone, unlock it, and trust the Mac
    First connection prompts a "Trust This Computer?" dialog on the iPhone — tap Trust.
  2. Enable Developer Mode on the iPhone
    iPhone→ Settings→ Privacy & Security→ Developer Mode→ Toggle ON
    Phone reboots once after enabling. Required for any dev build to launch on iOS 16+.
  3. Start the EAS build
    cd apps/mobile && eas build --profile development-device --platform ios
    EAS shows a QR code in the terminal and a build URL.
  4. Register the device UDID
    Scan the QR code from the iPhone Camera app — opens Safari → "Register this device with EAS" prompt → tap Register → returns the UDID to EAS, which adds it to the Apple Developer Portal automatically.
  5. Wait for the build (20-35 min)
    EAS Dashboard (web)→ Momento project→ Builds tab https://expo.dev/accounts/sangeetparashar24/projects/momento/builds
    Status progresses: queued → in-progress → finished. Click the build to see live logs.
  6. Install the build on the iPhone
    Once finished, the build page shows a QR code labelled "Install". Scan it from the iPhone Camera app → opens a signed install link → tap Install in Settings → app appears on home screen.
  7. Run Metro and open the app
    cd apps/mobile && npx expo start --dev-client
    Tap the Momento icon on iPhone → connects to Metro via LAN.
  8. Run device smoke test
    Verify: cold-start, Privy Google login, feed loads (location prompt), post detail, video playback, push permission prompt, like/follow, KYC flow, profile screen. Document failures.
iOS · Phase 8

TestFlight LaunchFirst build ~35 min + ASC setup ~30 min + Beta Review ~24h (external only)

Pending Phase 7

Builds a production-signed IPA, submits to App Store Connect, configures TestFlight, invites testers. Internal testers (up to 100) get instant access; external testers (up to 10,000) require a one-time Beta App Review.

Step 8a — Production build (terminal)

  1. Run the EAS production build
    cd apps/mobile && eas build --profile production --platform ios
    Auto-increments build number, signs with App Store distribution certificate, produces .ipa. Build takes ~25-35 min.

Step 8b — Submit to App Store Connect (terminal)

  1. Submit the latest build
    cd apps/mobile && eas submit --platform ios --latest
    Uses submit.production.ios in eas.json (Apple ID brian@mylz.run, ASC App ID 6762237065, Team 9BJL3C9DHA). EAS handles upload, Apple processes for 5-15 min before the build is visible in TestFlight.

Step 8c — Fill out TestFlight metadata (App Store Connect web)

  1. Open Momento in ASC
    App Store Connect home→ Apps tile→ Momento Network https://appstoreconnect.apple.com/apps/6762237065
  2. Switch to TestFlight tab
    App detail page→ Top tab bar: TestFlight
  3. Fill in "Test Information"
    TestFlight tab→ Left sidebar: Test Information
    Required fields:
    • Beta App Description: "Location-based creator platform with embedded Solana wallets. Discover and follow creators near you." (or your version)
    • Email: brian@mylz.run
    • Phone: contact number (visible to Apple reviewers only)
    • Privacy Policy URL: https://momento.network/privacy (must exist)
  4. Answer Export Compliance for the build
    TestFlight tab→ Left sidebar: iOS Builds→ Click the build (yellow "Missing Compliance" badge)
    You'll be asked: "Does your app use encryption?" — for standard HTTPS usage answer "None of the algorithms mentioned above" (covers normal TLS/HTTPS without custom crypto). Confirms within 30 sec, build status flips to "Ready to Submit".

Step 8d — Add internal testers (instant access)

  1. Open Internal Testing
    TestFlight tab→ Left sidebar: Internal Testing→ Plus icon (+) next to "Internal Testing"
  2. Create Internal Group
    Name it (e.g. "Momento Core Team"). Toggle "Enable automatic distribution" if you want new builds to auto-appear for testers.
  3. Add testers by email
    Testers must be added as Users in App Store Connect first (Users and Access tab). Then assign them roles like "Developer" or "Marketing" → they appear as available testers here. Limit: 100 internal testers, all on your ASC team.
  4. Attach the build to the group
    Click the group → "Builds" tab → "+" → select the latest build → adds it. Testers immediately get an email invite + push notification in the TestFlight app on their iPhone.

Step 8e — External testers (Beta App Review required)

  1. Open External Testing
    TestFlight tab→ Left sidebar: External Testing→ Plus icon (+)
  2. Create External Group
    Name it (e.g. "Momento Public Beta"). Choose whether to enable public link sharing.
  3. Submit build for Beta App Review
    Add the build to the group → status will be "Waiting for Review". Apple typically responds within 24 hours on the first submission. Subsequent builds for the same group only need re-review if there's a material change.
  4. After approval, invite testers
    Add by email up to 10,000 testers. Or copy the "Public Link" and share — anyone with the link can join (no email needed). Useful for a "join our beta" landing page.

05 Android — Play Store Distribution

Ten phases (GA-1 through GA-10), starting with a $25 one-time Play Console signup. Most of GA-1 through GA-5 is desk/web work — doable today, no device required. Phases A6+ require working FCM and a built AAB.

Android · GA-1

Create Google Play Console Account~30 min including ID verification

Pending

One-time $25 USD developer registration. Pick the email that will be the "developer of record" — recommend brian@mylz.run for symmetry with the Apple account.

  1. Open Play Console signup
    Browser→ play.google.com/console/signup https://play.google.com/console/signup
    Sign in with the Google account you want to own the listing.
  2. Choose account type
    Signup wizard→ "What kind of Play Console account?"→ Pick Organization
    Organization (vs Personal) is the right call for Momento — required for D-U-N-S number lookups, formal app store listings, and team-based access control later.
  3. Pay the $25 registration fee
    One-time, non-refundable. Card payment.
  4. Verify identity
    Upload a government-issued ID. Google may also require D-U-N-S number for orgs (free, lookup via Dun & Bradstreet). Verification can take 1-3 business days but you can proceed with app creation while waiting.
Android · GA-2

Create the Momento App Listing~10 min

Pending GA-1
  1. Open Play Console home
    Browser→ play.google.com/console https://play.google.com/console
  2. Click "Create app"
    Play Console dashboard→ Top-right button: Create app
  3. Fill out the create-app form
    • App name: Momento (or "Momento Network")
    • Default language: English (United States)
    • App or game: App

    Click Create app. You land on the new app's dashboard.

    The package name is locked at first upload, not here. Your AAB from EAS will declare com.momento.network — Play accepts whatever the AAB says on first upload.
Android · GA-3

Firebase Cloud Messaging Setup~15 min

Pending

Required for Android push notifications. Without google-services.json in EAS, push permissions silently no-op on Android.

  1. Open Firebase Console
    Browser→ console.firebase.google.com https://console.firebase.google.com
  2. Add a Firebase project (or reuse the one linked to Play later)
    Firebase home→ Add project
    Name it "Momento". Skip Google Analytics (optional). Wait for provisioning (~30s).
  3. Add an Android app to the project
    Project overview→ Click the Android icon (under "Get started by adding Firebase to your app")
    On the registration screen:
    • Android package name: com.momento.network
    • App nickname: Momento Android
    • Debug signing certificate SHA-1: leave blank for now (can add later for SHA-pinned features)
    Click Register app.
  4. Download google-services.json
    Firebase shows a download button. Save the file.
  5. Place it in the mobile app and reference it
    1. Copy to apps/mobile/google-services.json (gitignored).
    2. Edit apps/mobile/app.json: under "android", set "googleServicesFile": "./google-services.json".
  6. Skip "Add Firebase SDK" and "Verify"
    These are for native Android dev. Expo handles the wiring via the file you just dropped in. Click "Continue to console" / "Next" to dismiss the wizard.
Android · GA-4

Create Play Console Service Account~20 min, two dashboards

Pending GA-1

Required for eas submit -p android. Lives in Google Cloud (creation) but needs Play Console (permission grant) to actually push releases.

Part 1: Create the service account in GCP

  1. Open Google Cloud Console
    Browser→ console.cloud.google.com https://console.cloud.google.com
    Sign in as the same Google account that owns Play Console / Firebase.
  2. Select the Firebase-backed project
    GCP top bar→ Project picker dropdown→ Select "Momento" (auto-created when you added Firebase project)
  3. Open Service Accounts
    GCP Console→ Hamburger menu (top-left)→ IAM & Admin→ Service Accounts https://console.cloud.google.com/iam-admin/serviceaccounts
  4. Create a new service account
    Service Accounts page→ Top bar: + CREATE SERVICE ACCOUNT
    Fill in:
    • Name: momento-eas-submit
    • Description: "EAS submit to Play Store"
    Click Create and Continue.
  5. Grant minimal IAM role
    On step 2 of the wizard: under "Grant this service account access", add role Service Account User. Click Continue, then Done.
  6. Generate a JSON key
    Service Accounts list→ Click the new account's email→ Keys tab→ ADD KEY → Create new key→ Key type: JSON→ CREATE
    Browser downloads a .json file. Save it; you'll move it in GA-5.

    Play Console→ Left sidebar: Setup→ API access https://play.google.com/console/api-access

  3. Grant the service account Play Console permissions
    API access page→ Find momento-eas-submit@...iam.gserviceaccount.com→ Click Grant access

    • Account permissions: check Release apps to testing tracks and Release apps to production
    Click Invite user (despite the name, it grants the service account immediately).

Android · GA-7

First Manual Upload (Internal Track)~15 min

Pending GA-6

Google requires a manual first upload before eas submit can push to a track. Subsequent submits are CLI-only.

  1. Open Internal Testing
    Play Console→ Momento app→ Left sidebar: Testing→ Internal testing
  2. Create a new release
    Internal testing page→ Top-right: Create new release
  3. Upload the AAB
    Drag the .aab from EAS (or click "Upload" and pick the file). Play verifies signing and parses the manifest. Bundle name should resolve to com.momento.network.
  4. Complete app signing setup
    First-time uploads trigger the Play App Signing flow. Accept Google's default: Let Google manage and protect your app signing key. Play takes over key custody.
  5. Fill release name and notes
    • Release name: "1 (1.0.0)" or whatever EAS named it
    • Release notes (en-US): "Initial internal testing build"
    Click Next, then Save.
  6. Review and roll out
    Click Review release → resolve any warnings (will likely flag missing privacy policy, content rating, data safety — see GA-7b below) → Start rollout to Internal testing.
Mandatory Play Store listing fields (block release if missing):
  • App content: Privacy Policy URL (https://momento.network/privacy), Ads declaration, Content rating questionnaire (~10 min via IARC), Target audience, Data safety form
  • Store listing: Short description (80 char), Full description (4,000 char), App icon 512×512, Feature graphic 1024×500, at least 2 phone screenshots
Fill these from the left sidebar under Grow → Store presence and Policy → App content. Plan ~1 hour total.

Android · GA-10

Promote Internal → Closed → Open → ProductionPer-stage; Production review can take 3-7 days first time

Endgame

Each track is a wider audience. Closed and Open testing require tester lists (or a Google Group). Production goes to everyone on the Play Store.

  1. Open the source track
    Play Console→ Testing → Internal testing→ Releases tab
  2. Promote the release
    Release row→ Three-dot menu (or "Promote release" button)→ Pick destination: Closed / Open / Production
  3. For Closed/Open testing
    • Closed: same flow as internal but tester lists can be larger and reviewed (~24h first time).
    • Open: anyone with the opt-in URL can join; reviewed first time (~24h).
  4. For Production
    Full Play Store review. First submission takes 3-7 days. Subsequent updates: usually < 24 hours. Make sure Store listing + App content are complete (GA-7 warning).

06 Pointing momento.network at Vercel

Right now momento.network is parked on GoDaddy (responses include Server: DPS/2.0.0). The Vercel landing project exists but isn't reachable via the apex domain yet. One-time DNS task.

  1. Add the domain to the Vercel landing project
    Vercel Dashboard→ landing project→ Settings tab→ Domains→ Add momento.network
    Vercel shows you the exact DNS records to add (A record for apex, CNAME for www).
  2. Update DNS at GoDaddy
    GoDaddy account→ Domain Portfolio→ momento.network→ DNS tab https://dcc.godaddy.com/manage/MOMENTO.NETWORK/dns
    Delete the existing "Parked" A record. Add Vercel's records:
    • A — Name: @ — Value: 76.76.21.21 (Vercel's apex IP)
    • CNAME — Name: www — Value: cname.vercel-dns.com
  3. Wait for DNS propagation
    ~5 min to a few hours. Verify with: 
    dig momento.network +short
curl -sI https://momento.network | head -5
    Response should show Vercel's edge (e.g. x-vercel-cache headers) once propagation is complete.
  4. Verify this doc loads at the new domain
    https://momento.network/distribution.html should serve this file.
